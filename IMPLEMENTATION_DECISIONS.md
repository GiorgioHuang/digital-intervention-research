# IMPLEMENTATION_DECISIONS

> The implementation-level disposition of every open ADR in Appendix C (ADR-101…125) and of the two settled ADRs that are Pending. Statuses: `Adopted for Implementation` (adopted by the implementation, awaiting formal ADR approval) / `Proposed` / `Blocked` / `Pending External Approval` / `Not Applicable`. There is no pre-existing code in this repository that would settle any of these ADRs in advance (it is greenfield). This file does not constitute formal approval; the decision packages (≥2 alternatives, security/privacy/residency review, and so on) are completed separately by the governance process.

## The conformance statement for the settled ADRs

ADR-001…060 are all followed exactly as Accepted / Deferred / Prohibited; the implementation enables no Deferred or Prohibited capability (ConnectionRequest, Internet Public, broadcast messaging, autonomous high-impact AI and the rest exist in an explicitly disabled state and return a stable error code). ADR-048/049 (pilot design, phased activation) are Pending Approval: the software is implemented in their shape, but activation is conditional on approval.

## The outstanding approval dependencies, summarised

Ethics and the pilot (ADR-048/049, ATR-025); provider contracts (ADR-103/105/109/111/114/126 — **ADR-104 is settled as Sign in with Google and implemented; ADR-106 object storage is settled as Cloudflare R2 and connected, with the real round-trip still to be verified**); policy values (ADR-119/120/121/123/124/125); matching and ordering policy (ADR-112/113); the analysis environment (ADR-115); the encryption policy (ADR-117). All of them are handled on the principle of "the interface and a simulator first, configuration-driven, failing closed, and never faking an approval", and none of them blocks unrelated workflows.

## Supplementary chapter for the conceptual research mode (2026-07-31, the Master Prompt v1.2 / README v2.9 baseline)

- The project mode changed: from a production-track MVP to conceptual research with an executable prototype (Doc 1 v2.2 §3.1, Docs 18/19/20 v1.3). The disposition of the existing ADR-101…125 is **unchanged** — they describe architectural choices of the system being modelled, and their "Pending External Approval" marking is now read as "an approval needed only on the transition to the empirical phase", not as a gate on the current research (Doc 18 §3.2).
- ADR-061…064, cited by the Master Prompt: **registered as CON-002 when they were absent** from the repository (Appendix C v1.0 stopped at ADR-060) and no content was invented for them; the mode change was recorded from the body of the new documents instead. **CON-002 is now Resolved (2026-08-01)**: Appendix C v1.2 has been uploaded and all four are on disk — ADR-061 (conceptual research is the current mode, Accepted), ADR-062 (synthetic data / simulated actors / simulated providers, Accepted), ADR-063 (no external approval gate for the current conceptual work, Accepted) and ADR-064 (empirical human-subjects research is a separate future project, Deferred).
- Prototype engineering choices (against Doc 18 §137/§115): the existing stack falls entirely inside the permitted range (local PostgreSQL, pg-boss, simulators, a non-production UI); there are no microservices, no Kubernetes, no multi-region and no production identity — consistent with "Do not over-engineer". `Adopted for Prototype`.
- The production-readiness artefacts (PILOT_READINESS_REPORT and the rest) keep describing their original context faithfully; their conclusion that no real recruitment may take place still holds under the conceptual mode, and holds more strongly (Doc 19 §32: no human subjects).
